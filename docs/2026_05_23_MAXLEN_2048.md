# AI Detector Project — Work Summary So Far

## 1. Main problem discovered

We were investigating why the mixed-sample grid detector reported:

```text
truth_blocks  = 480
scored_blocks = 481
```

for every block-size setting.

The specific example was:

```text
src/app/data_mixed_samples_grid_480/blocks_02/mixed_sample_174.py
```

The labels file showed only two intended blocks:

| Block | Function    | Label   | Source idx       |
| ----: | ----------- | ------- | ---------------- |
|     1 | `checkargs` | `lm`    | `line2179_lm`    |
|     2 | `start`     | `human` | `line1799_human` |

But the detector extracted three top-level blocks. We traced the issue to `line2179_lm`.

## 2. Root cause

The raw StarCoder2-Instruct output for one sample was supposed to be **function body only**, but it repeated the full function signature:

```python
def checkargs(self, lineno, command, args):
    ...
```

After composing `prompt + output`, the final code became:

```python
def checkargs(self, lineno, command, args):
    """
    docstring
    """

def checkargs(self, lineno, command, args):
    ...
```

This is syntactically valid Python, but it contains **two top-level functions in one CSV row**.

That broke the mixed-sample assumption:

```text
one CSV row = one top-level function/class block
```

## 3. Fix applied to `find_validsyntax_mgc.py`

We edited:

```text
src/code-generation/find_validsyntax_mgc.py
```

| Fix                                                            | Purpose                                                |
| -------------------------------------------------------------- | ------------------------------------------------------ |
| Strip repeated outer `def` / `class` signatures                | Salvage outputs that repeat the function header        |
| Require exactly one top-level function/class after composition | Reject structurally invalid rows even if syntax-valid  |
